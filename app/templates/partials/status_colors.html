{# ============================================================================ partials/status_colors.html — Batch 159-2 ONE global, semantic colour system for every status label in the app (images 1, 2, 3, 4, 5, 16, 17). CSS can't colour by text, so a tiny script reads each status label and applies a semantic pill: green = good (Approved, Delivered, Passed, Completed, On track, Exact) blue = info (Packed, Dispatched, Submitted, BOM Generated, Ready) cyan = progress (In Production, Out for Delivery, Cooking, Processing) amber = warn (Pending, Awaiting, Delay, Excess, On Hold) red = bad (Rejected, Short, Cancelled, Overdue, Failed) purple = accent (Tomorrow / due soon) It is deliberately VOCABULARY-DRIVEN: it only touches elements whose text is a known status (or that carry data-status), so counts like "12 bags", "Corporate" or "Normal" are never recoloured. It also wraps plain-text cells sitting under a column header named STATUS. Runs on load and re-runs (guarded) when tables are re-rendered by list.js. ============================================================================ #}
